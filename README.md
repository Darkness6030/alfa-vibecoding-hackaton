# AlfaGen PII Guard

Модуль защиты персональных данных между системой-потребителем и LLM: идентификация 17 категорий ПД, маскирование, точное демаскирование, политики потребителей, безопасность и наблюдаемость.

## Статус (K10)

**Релиз подготовлен.** ZIP `dist/alfagen-pii-guard-0.1.0.zip`, commit `d0f58e2` (tag `v0.1.0`), URL `http://5.42.98.110:8000`. Чек-лист сдачи — `docs/delivery-checklist.md`. Презентация и скринкаст — отдельные артефакты (не созданы).

## Назначение и схема

```
Потребитель → детекция → маска (токены) → LLM → проверка ответа → детокенизация → потребитель
```

- **Путь стенда:** `POST /process` — точный протокол проверки, без вызова LLM.
- **Путь демо-прокси:** `POST /proxy` (demo-secure) — через то же ядро, с mock LLM и детокенизацией ответа.

## Контракт

```
POST /process
{"payload": string, "payload_id": string}  ->  200 {"result": string}
```

Оба поля обязательны и имеют тип string; `result` — string. Ошибки валидации — `422`, конфликт — `409`, запрет доступа — `401/403`, перегрузка — `429` с `Retry-After`, хранилище недоступно — `503`, внутренние — `500`. Ошибки не отражают входные данные.

## Запуск

Перед тестированием остановите другие контейнеры, занимающие порт 8000 (например, существующий `pii-guard`-проект), иначе `docker compose up` упадёт с «port is already allocated».

```bash
docker compose up --build
curl http://localhost:8000/health
curl -X POST http://localhost:8000/process \
  -H 'Content-Type: application/json' \
  -d '{"payload":"Иван Иванов","payload_id":"id-1"}'
```

## Настройка (5 предложений)

Настройки задаются переменными окружения с префиксом `ALFAGEN_`. `ALFAGEN_PROFILE` выбирает профиль (`evaluation-open` или `demo-secure`). `ALFAGEN_REDIS_URL` задаёт Redis, `ALFAGEN_STATE_TTL_SECONDS` — срок пары (по умолчанию 900 с). `ALFAGEN_ENCRYPTION_KEY` — общий ключ шифрования соответствий (обязателен для нескольких workers). `ALFAGEN_MAX_CONCURRENCY` — лимит параллельных запросов. Подробности — в `app/config.py`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `ALFAGEN_PROFILE` | `evaluation-open` | Профиль: `evaluation-open` или `demo-secure` |

## Политики систем

- **`evaluation-open`:** одна открытая система для стенда, без API-ключа, демаскирование разрешено. Временное исключение аутентификации для проверки, не банковский контур.
- **`demo-secure`:** две системы по API-ключу (`X-API-Key`): `crm` (маскирует PERSON/EMAIL/PHONE/INN/CARD/ADDRESS, демаскирует) и `analytics` (маскирует EMAIL/PHONE, демаскирование запрещено). Отзыв доступа действует немедленно; параметры пары неизменны.

## Покрытие категорий

Все PD01–PD17 представлены (таблица — `docs/category-coverage.md`). Примеры прямого/обратного запроса и политики ретраев/TTL — в `docs/decisions.md` (D05).

## Метрики и логи

- `/metrics` — Prometheus-формат с multiprocess-агрегацией: HTTP-запросы, latency, пары, ошибки, detected/masked по типам.
- Логи безопасные: этап, система, created, latency — без входных значений и ПД.
- Отчёт нагрузки — `docs/load-report.md`; качество — `docs/quality-report.md`.

## Бонусные сценарии

1. **Токенизация** — непрозрачные типизированные токены `{{TYPE:hex}}` (встроено).
2. **Выбор режима по системе** — `mask_types`/`demask_allowed` настраиваются по системе.
3. **Правило сочетания типов** — приоритеты пересечений (например, карта побеждает над общим числом).

## Ограничения

- Runtime LLM — **заглушка (mock)**, явно подписана в UI/README; не выдаётся за реальную генерацию. Качество реальной LLM и живая интеграция не проверены.
- Все 17 категорий представлены, но качество на реальных банковских текстах не измерено; наборы синтетические (P/R/F1 = 1.00 на локальном наборе).
- Natasha NER — опциональный кандидат-генератор; без него полнота LOC/PER ниже (regex-фолбэк).
- 1000 RPS не достигнуто (макс ~283 RPS); узкое место — Redis round-trip.
- Ключ шифрования: если `ALFAGEN_ENCRYPTION_KEY` не задан, генерируется эфемерный при старте (соответствия теряются при рестарте, не общий для workers).
- Профиль `evaluation-open` — временное исключение аутентификации, не банковский контур.
- Ни исходные ПД, ни секреты не попадают в логи/ошибки/артефакты.
