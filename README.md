# AlfaGen PII Guard

Модуль защиты персональных данных на Python/FastAPI: 17 категорий, RU/EN-контексты, обратимые токены, политики потребителей, Redis и явно обозначенная заглушка LLM. Основной код создан DeepSeek-V4-Flash-0731 в Kilo; последующие доработки выполнены в Codex по разрешению участника.

**Версия 0.4.4.** Контекстное распознавание RU/EN, точная обратимость и настройки потребителей. Официальная оценка исходников **10000/10000** — подтверждена участником для финального ZIP 0.4.4. Локальная проверка Sonar way на Sonar 25.9, 26.1 и 26.9: 0 issues / 0 security hotspots. HTTPS-прокси использует пул соединений к API и HTTP/1.1. Оценка относится к автоматической проверке качества кода.

## Запуск

Python 3.12 и Docker Compose (рекомендуется от 4 GiB RAM); для overlays нужна поддержка `!override`.

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python scripts/generate_demo_secrets.py
docker compose up -d --build
curl http://127.0.0.1:8000/ready
```

Генератор создаёт `.env` и `.secrets/tls`, не печатает ключи и отказывается перезаписывать существующие. Для другого IP передать `--ip`; сертификат демо действует 7 дней. Секреты в репозиторий/ZIP не включать. Порт меняется через `ALFAGEN_PORT`, binding по умолчанию `127.0.0.1`.

Опциональный HTTPS:

```sh
docker compose -f docker-compose.yml -f docker-compose.tls.yml up -d
curl -k https://127.0.0.1:18443/ready
```

`-k` нужен только для согласованного self-signed демо; HTTP не является защищённым транспортом. При обновлении API сохраняйте ключ, namespace и Redis активных пар; пересоздавайте только API.

## Настройка: пять предложений

Параметры окружения имеют префикс `ALFAGEN_`, а JSON-политики находятся в `config/policies.json`. Профиль `evaluation-open` открывает только `/process` для стенда, а `demo-secure` требует ключ потребителя. Для системы задаются enabled, detect_types, mask_types, masking_enabled, demask_allowed, mask_mode и combinations. При изменении файла политики перечитываются, и отзыв права применяется также к уже сохранённым парам. Секреты задаются через окружение, TTL по умолчанию 900 секунд, лимит тела 8 МБ (с учётом увеличения текста после токенизации), лимит зашифрованной пары 16 МБ, конкурентность 32 на worker, число workers — `ALFAGEN_WORKERS`.

| Переменная | Назначение |
|---|---|
| `ALFAGEN_ENCRYPTION_KEY` | Обязательный общий Fernet-ключ для всех workers |
| `ALFAGEN_CRM_API_KEY` / `ALFAGEN_ANALYTICS_API_KEY` | Ключи потребителей; CRM разрешён proxy, analytics запрещено восстановление |
| `ALFAGEN_METRICS_API_KEY` | Ключ чтения метрик |
| `ALFAGEN_STATE_NAMESPACE` | Изолированное пространство пар прогона |
| `ALFAGEN_STATE_TTL_SECONDS` | Время хранения; повторы TTL не продлевают |
| `ALFAGEN_MAX_BODY_BYTES` / `ALFAGEN_STATE_MAX_RECORD_BYTES` | Ограничения тела и записи |
| `ALFAGEN_REDIS_MAXMEMORY` / `ALFAGEN_REDIS_MEMORY_LIMIT` | Ёмкость Redis / память контейнера; по умолчанию 1024mb / 1280m |
| `ALFAGEN_MAX_CONCURRENCY` / `ALFAGEN_WORKERS` | Конкурентность и процессы |
| `ALFAGEN_PORT` / `ALFAGEN_TLS_PORT` / `ALFAGEN_BIND` | Порты и интерфейс публикации |

`mask_mode` поддерживает `token` и `redact`. `"combinations": {"PIN": ["CARD"]}` задаёт ослабляющую политику для демонстрации сочетаний; это не default и не допустимая политика proxy. Новый тип: `custom_patterns` с `type` и `pattern`, затем включение в detect_types/mask_types. Редактировать такие regex должен доверенный администратор. Невалидная политика приводит к контролируемому отказу до исправления. При атомарной замене bind-mounted JSON может потребоваться пересоздать API для обновления inode.

Для воспроизводимого показа конфигураций: `.venv/bin/python -m benchmarks.demo_policies`. Скрипт на синтетических значениях проверяет новый тип EMPLOYEE_ID, token/redact, запрет восстановления и сочетание PIN+CARD, не меняя запущенный сервис. Вывод сокращает случайные токены до имени типа; правило PIN+CARD намеренно оставляет одинокий PIN открытым и запрещено для proxy.

## Контракт

```http
POST /process
Content-Type: application/json

{"payload":"Customer John Smith, email john@example.com","payload_id":"unique-pair-1"}
```

Успех: `200 {"result":"..."}`. Новый id создаёт маску; повтор оригинала возвращает прежнюю маску; запрос с той же маской/id возвращает оригинал точно после проверки права. Иное содержимое при том же id — 409. В защищённом профиле нужен `X-API-Key`; новых полей в официальный JSON добавлять не надо.

Ошибки: 401/403 доступ, 409 конфликт/нет токенов в состоянии, 413 размер тела, 422 схема, 429 перегрузка с Retry-After, 503 хранилище/конфигурация, 500 безопасная внутренняя ошибка. Значения входного текста не отражаются в ошибках.

## Демо, логи и метрики

Открыть корневую страницу, ввести CRM-ключ из окружения владельца. Интерфейс показывает маску на границе mock, его ответ и восстановленный текст. Ключ не сохраняется в браузере. `/proxy` требует полную безопасную token-политику; в UI явно подписана заглушка. Mock разрешён организаторами и не считается незакрытым требованием живой LLM.

Логи: `docker compose logs api`; они содержат стадии, типы, исход обработки и длительности без ПД. `/metrics` принимает `X-Metrics-Key` либо ключ разрешённого потребителя; `/health` проверяет процесс, `/ready` — Redis. RPS/TPS — rate соответствующих счётчиков, TPS технический, не billed tokens модели. Гистограмма различает HTTP и внутренние этапы; вложенные времена не суммировать. Multiprocess-метрики агрегируются.

## Проверки и минимальный ZIP

```sh
.venv/bin/python -m pytest -q
.venv/bin/python benchmarks/quality_metrics.py
.venv/bin/python scripts/check_docs.py
.venv/bin/python scripts/build_release.py 0.4.4
```

Сборщик создаёт `dist/alfagen-pii-guard-0.4.4.zip`, не заменяет существующий файл, отказывает на symlink и использует явный список исходников/файлов запуска. В ZIP включены также переносимые файлы HTTPS-запуска; README/docs, tests/benchmarks, окружений, сборок, медиа и секретов в нём нет — это формат для проверки кода по просьбе участника. **README и инструкции должны быть доступны жюри через сдаваемый репозиторий:** их отсутствие у решения обнуляет критерий настройки. Архив, репозиторий и deployment перед сдачей должны соответствовать одной версии.

Исторический проверенный ZIP 9890 сохранён в `dist/archive/`. Документация/тесты остаются в репозитории. Старые промпты и временные сборщики удалены; упаковка теперь одна.

Для нагрузки готового сервиса:

```sh
.venv/bin/python benchmarks/load_test.py --url http://127.0.0.1:8000 --rps 1000 --profile qa-ramp --duration 300 --concurrency 256 --corpus benchmarks/corpus-mixed.json --output output/load.json
```

QA-ramp задаёт среднее предложение 327,5 HTTP RPS и пик 1000; отчёт содержит успешный RPS, mean/p50/p95/p99, ошибки, 429 и dropped. Точная кривая жюри неизвестна. Нагрузку не запускать на соседних сервисах без согласованного окна.
