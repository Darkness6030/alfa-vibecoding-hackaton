## 2. Решения, на которых строится план

Один Python/FastAPI-проект, Redis для общей временной пары, regex/контекст плюс ранний эксперимент с локальным Slovnet/Navec, простая HTML-страница, Docker Compose. `/process` не вызывает LLM. Отдельный демопрокси использует то же ядро и mock LLM с изменением окружения токенов. По умолчанию токенизация, TTL 15 минут с лимитами памяти, изолированные `demo-secure` и `evaluation-open` профили.

Начать с одного процесса, измерить 2/4, только затем добавлять workers; у Dental 8 logical CPU и 11 GiB RAM. Production-готовность не оценивается. Честные измерения и показ настроек приносят баллы; неподтверждённая сложная инфраструктура их не заменяет. Цель критериев — 0,5 с/1000 RPS, исходное ТЗ — 1 с/1000 RPS; ни один показатель пока не измерен.

## 5. Приёмочные проверки

1. JSON-контракт и корректные ошибки без отражения входных ПД.
2. Повторы каждого шага, гонки, конфликтующий текст, маска=оригинал, TTL/рестарт/несколько workers; ограниченное состояние.
3. PD01–PD17, вариации регистра/дат/разделителей, смешанные категории, отрицательные примеры и контекстные исключения.
4. Точное восстановление Unicode, пробелов и пунктуации; ответ mock с перемещёнными токенами; неизвестный/повреждённый токен не восстанавливается наугад.
5. Две политики, включение/отключение потребителя и маскирования, запрет демаскирования; отдельное временное исключение для `/process`.
6. Отказ Redis/защиты не приводит к раскрытию; синтетических ПД-маркеров нет в технических логах/ошибках/метриках, а в архиве нет секретов и реальных ПД; небольшие синтетические fixtures для тестов допустимы.
7. 100 000 токенов по объявленному токенизатору без усечения; RPS и latency на описанном профиле; multiprocess метрики охватывают весь сервис.
8. Чистый Docker-запуск из сданного ZIP, внешний URL, работающий README, совпадение commit/образа/архива, воспроизводимые материалы демо.

## 6. Что сокращать первым

Декоративный UI, дополнительные документы кроме паспорта, сложную синтетику, необязательные интеграции, многоуровневую оркестрацию. Базовая токенизация уже может дать бонус; не пытаться во что бы то ни стало получить 2000 RPS. Обязательные категории, обратимость, README, метрики и доступность не вычёркиваются молча: любой непокрытый пункт становится явным риском сдачи.

Сохранять рабочий commit после каждого этапа. Последний час не тратить на смену архитектуры/зависимостей. Реализация отсутствующего обязательного поведения важнее косметики; резерв на ZIP, презентацию и видео неприкосновенен.
