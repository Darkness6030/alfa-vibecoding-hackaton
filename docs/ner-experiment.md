# K4a: Опыт Natasha/Slovnet/Navec — результаты и решение

Дата: 22.09.2026. Воспроизводимый набор: `benchmarks/synthetic_ner.py` (16 синтетических предложений с известными PER/LOC). Запуск: `docker build -f benchmarks/Dockerfile.ner -t alfagen-ner-bench:0.1.0 . && docker run --rm alfagen-ner-bench:0.1.0`.

## Результаты (Docker, python:3.12-slim, natasha 1.4.0)

| Метрика | Natasha NER | Regex baseline |
| --- | --- | --- |
| PER precision / recall / F1 | 1.00 / 1.00 / 1.00 | 1.00 / 1.00 / 1.00 |
| LOC precision / recall / F1 | 1.00 / 1.00 / 1.00 | 1.00 / 0.86 / 0.92 |
| Время на предложение (после warmup) | ~0.8 ms | ~0.1 ms |
| Пиковая память | ~188 MB | ~0.1 MB |
| Размер образа | 408 MB (веса в образе, офлайн) | — |

## Выводы

- **Качество:** Natasha даёт идеальные PER/LOC на наборе; regex пропускает одну склонённую форму города («Казани»), F1 LOC 0.92 против 1.00.
- **Скорость:** после однократной загрузки модели ~0.8 ms/предложение — пренебрежимо для цели ≤0.5 с.
- **Память:** ~188 MB на процесс (модель загружается один раз и переиспользуется). Приемлемо для сервера 11 GiB.
- **Офлайн:** веса в образе, запуск без сети работает.

## Решение: включить Natasha NER как дополнительный детектор

**Включить** Natasha NER как кандидат-генератор PER/LOC для категорий ФИО (PD01) и места/адреса (PD03/PD10). Основания:
1. Улучшает полноту LOC (0.86 → 1.00) при пренебрежимой задержке (~0.8 ms).
2. Модель загружается один раз (singleton) и переиспользуется между запросами.
3. Офлайн-работа подтверждена.

**Ограничения:**
- Natasha выдаёт PER/LOC/ORG, а не 17 банковских категорий; это кандидат-генератор, а не полное решение. Regex/контекстные правила остаются обязательными.
- Качество на новостях не равно качеству на документах/переписке; набор синтетический и мал (16 случаев). Реальная полнота на банковских текстах не измерена.
- 188 MB на процесс и 408 MB образ — цена включения; при нескольких workers память растёт линейно.
- Точные границы span могут включать пунктуацию (проверено: на наборе совпали точно).
