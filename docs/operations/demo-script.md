# Демо за 1–2 минуты

Проводить на окончательно проверенном билде; версии видео/слайдов/сервиса должны совпадать. Только синтетические значения. CRM-ключ ввести до записи, не показывать env/заголовки/историю терминала с секретом.

1. **0:00–0:20:** объяснить цепочку «потребитель → обнаружение и токены → mock LLM → восстановление». Показать надпись mock, сказать, что он разрешён QA и переставляет токены для проверки обратимости.
2. **0:20–0:50:** отправить смешанный текст, например `Customer José García; дата рождения 15 марта 1990 года; Phone: +44 20 7946 0958; Email: jose@example.com`. Показать, что на входе mock нет этих значений, служебные слова сохранены, ответ потребителю восстанавливает значения. Повторить русский паспорт/адрес и литературный/банковский отрицательный пример.
3. **0:50–1:15:** показать конфиг двух потребителей, запрет демаскирования analytics и добавление простого custom типа без правки ядра. Отдельно показать три возможности: token/detokenize, token/redact, комбинация PIN+CARD. Ослабленные комбинации не использовать для proxy.
4. **1:15–1:40:** показать безопасный лог этапов и метрики/результат свежего нагрузочного прогона. Назвать успешный RPS, p95/p99 и среду; 429 отдельно от ошибок. Не суммировать вложенные времена стадий.
5. **1:40–2:00:** назвать ограничения: эвристическое контекстное обнаружение, не все зарубежные документы/адреса, качество на скрытом наборе неизвестно, Redis TTL/потеря после рестарта. Указать понятное дальнейшее развитие: независимая языковая выборка и проверка банковского контура.

Если подготовлен только исторический нагрузочный отчёт, назвать его версию и не приписывать цифры текущему билду. При пропуске чувствительного значения на демо признать дефект, не выдавать точный round-trip за защиту. Схема, конфиги и инструкция должны быть доступны по репозиторной ссылке, хотя минимальный ZIP предназначен только для проверки кода.

## Подготовленный скринкаст 0.4.4

Финальное видео последовательно показывает архитектуру, реальный RU/EN proxy, четыре запроса одной пары, запрет analytics, изолированный демонстрационный конфиг и результаты нагрузки. Все примеры синтетические, озвучка синтезирована локально голосом Milena. Демонстрационный клиент скрывает ключи; операции `/process` и `/proxy` выполняются на развёрнутом сервере. Сцена добавления типа запускает реальную библиотеку с временным JSON-конфигом и явно отличается от работы удалённого сервера.

Для живой короткой защиты использовать первые два пункта сценария, затем `python -m benchmarks.demo_policies` и актуальную таблицу из [отчёта](../performance.md). Исторические 10000 за статический анализ относятся к ZIP 0.4.2; локальные проверки 0.4.4 не заменяют новый официальный прогон.
