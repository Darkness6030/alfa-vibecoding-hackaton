## Минимальный стек и границы

Предлагается один Compose-проект: приложение FastAPI/Uvicorn, Redis, простой TLS reverse proxy. Python 3.11 — стартовая гипотеза совместимости компактных NLP-зависимостей, подтвердить сборкой в первый час; фиксировать фактически прошедшие версии и хеши весов. Не обновлять зависимости перед сдачей. Одна статическая HTML-страница, отдаваемая приложением, достаточна для демо; отдельный frontend-фреймворк и база SQL не нужны.

Поток: потребитель → проверка доступа и политики → детекторы → разрешение пересечений → токенизация → сохранение соответствий → LLM получает только обработанный текст → проверка ответа/детокенизация → авторизованный потребитель. `/process` — адаптер официальной проверки, обходящий вызов LLM. Отдельный защищённый endpoint прокси нужен для реальной цепочки, явных направлений и ответа LLM, который изменил порядок/окружение токенов. Названия этих служебных endpoints можно выбрать при реализации, не меняя `/process`.

Сначала один worker для отладки, затем замер 2/4/8 workers с учётом памяти. Workers используют общий Redis. FastAPI документирует, что процессы имеют отдельную память и отдельные копии моделей; увеличение числа workers само по себе не доказывает линейное ускорение. Для одного Compose-сервера допустимы несколько Uvicorn workers в контейнере. [FastAPI: память и процессы](https://fastapi.tiangolo.com/deployment/concepts/), [FastAPI: Docker](https://fastapi.tiangolo.com/deployment/docker/).

## Детектирование: три уровня, одна система координат

1. Компилируемые при старте правила для структурированных значений: email, телефон, ИНН, карта, паспорт, водительское удостоверение, код подразделения. Число само по себе не равно ПД: учитывать длину, разделители, ближайшую метку, конкурирующие категории. Контрольные суммы использовать как свидетельство уверенности, а не универсальную причину пропустить явно подписанное значение: синтетический тест может содержать невалидную контрольную цифру.
2. Ограниченные контекстные окна и словари для даты/места рождения, даты выдачи, гражданства, выдавшего органа, адреса, CVV, PIN, имени держателя. Для каждой категории задать маркеры начала/конца и негативные примеры. Не делать «все даты — дата рождения», «все города — адрес клиента», «все три цифры — CVV». Даты `мм.дд.гггг` и текстовые месяцы проверять отдельно. Не нормализовать сам возвращаемый текст.
3. Компактный локальный NER Slovnet + Navec для кандидатов ФИО и географии; Natasha/Razdel — при необходимости сегментации и удобного API. Slovnet обучен на новостях и выдаёт PER/LOC/ORG, а не 17 банковских категорий. Его качество на новостях не равно качеству на документах/переписке. Веса NER и словарь Navec загружать при сборке образа или подготовке артефактов, запуск должен работать без сети. Исторический benchmark авторов нельзя переносить на наш сервер или на RPS `/process`. [Slovnet](https://github.com/natasha/slovnet), [Natasha](https://github.com/natasha/natasha).

Рекомендация — включить NER в ранний сравнительный эксперимент на одинаковом наборе; оставить его, если он улучшает полноту ФИО/адресов при приемлемой цене CPU. Не откладывать этот опыт до вечера 23 сентября. Контекстные правила и regex остаются необходимыми при любом результате. Не заявлять поддержку ФИО только на основании regex трёх слов с заглавной буквы: это ломается на нижнем регистре и обычных фразах. Если NER выключен, явно показать потерю качества, а не выдавать облегчённый профиль за тот же сервис.

Все детекторы возвращают исходные символьные интервалы, тип и основание. Для регистронезависимого поиска использовать поддерживаемые Unicode-операции с сохранением исходных смещений; не переносить индексы из строки после произвольной нормализации/транслитерации. Предпочесть ограниченные шаблоны; избегать вложенных неограниченных повторов на большом тексте. `re` поддерживает Unicode и скомпилированные шаблоны. [Python re](https://docs.python.org/3/library/re.html).

Пересечения разрешать детерминированно: специальный тип перед общим, подтверждённая граница перед сомнительной, затем стабильный приоритет. Маскировать объединённые покрытые интервалы без двойной замены; типы для аудита хранить отдельно. Обязательно проверить паспорт рядом с телефоном, дату в адресе/документе, имя держателя рядом с ФИО. Исключение «поэт Александр Пушкин» применять к конкретному контексту, а не к глобальному разрешённому имени: «клиент Александр Пушкин, паспорт…» должен оставаться персональным. Аналогично адрес офиса и адрес проживания одного текста нельзя исключать вместе.

## Токенизация и обратимость

Базовая замена — токен с типом, уникальной областью запроса и номером сущности, не содержащий частей исходного значения. Тип помогает LLM сохранить смысл. Случайная область должна исключать совпадение с пользовательским текстом и межзапросную подстановку. Маска CVV/PIN не оставляет цифр. Одинаковая сущность в запросе может иметь один токен, но разные исходные написания требуют отдельных значений, если необходимо дословное восстановление.

Сборка результата из исходных срезов сохраняет внешнюю пунктуацию, пробелы, переносы и Unicode. Обратная операция восстанавливает исходные срезы по токенам, поэтому точная маска даёт точный оригинал, а ответ LLM с переставленными целыми токенами — соответствующий изменённый текст. Не заменять весь ответ LLM сохранённым исходным запросом. Повреждённые/неизвестные токены не угадывать; возвращать контролируемую ошибку либо оставлять безопасный непрозрачный токен с явным статусом в служебном API. Политику выбрать и проверить. Это ограничение раскрыть в демо.

LLM может сгенерировать новые ПД или повторить ПД из внешнего контекста: выполнить детектирование его ответа до разрешённой детокенизации. Собственные валидные токены исключать из этого детектирования. Восстановленные данные возвращать только потребителю с соответствующей политикой; не отправлять восстановленный ответ обратно в LLM в следующем ходе. Историю диалога перед внешним вызовом обрабатывать тем же модулем. Для скринкаста и внешнего LLM использовать только синтетические примеры.

## `/process`: неизменяемая пара вместо переключателя

Ключ состояния включает пространство запуска, систему и непрозрачное представление `payload_id`. У официального теста система берётся из настройки маршрута; не требовать новых JSON-полей. Запись: версия политики, маска, таблица токенов, криптографические отпечатки исходного и обработанного текста, время создания/истечения. Секреты и исходные фрагменты шифровать; исходный текст при необходимости восстанавливается из маски и таблицы, его отдельная копия необязательна.

| Ситуация | Действие |
| --- | --- |
| ID отсутствует, вход — обычный текст | Вычислить маску, атомарно сохранить готовую запись с TTL, вернуть маску |
| ID есть, вход совпадает с исходником | Вернуть сохранённую маску; это повтор первого шага |
| ID есть, вход совпадает с сохранённой маской | Вернуть исходник, если демаскирование разрешено; это второй шаг и его ретраи |
| Исходник равен маске, например ПД не найдено | Вернуть тот же текст без переключения состояния |
| ID есть, вход иной | `409`, не раскрывать сохранённый исходник |
| ID отсутствует, вход содержит токен нашего формата | Контролируемая ошибка отсутствующего/истёкшего состояния, не притворяться успешной демаскировкой |

Запись не удаляется после первого обратного запроса: иначе второй ретрай не восстановит результат. Начальный TTL 15 минут — гипотеза для пятиминутного прогона и повторов, а не требование организатора. Сделать TTL настраиваемым; по умолчанию срок абсолютный от создания, чтобы постоянные ретраи не удерживали ПД бесконечно. Обратный запрос после TTL должен предсказуемо ошибаться. Между прогонами пространства ID менять только после завершения пар; совпадения ID между прогонами без сведений о запуске принципиально неразличимы.

Для конкурентного первого обращения два workers могут вычислить разные случайные токены. Победитель сохраняет полную запись одной операцией `SET NX EX`; проигравший читает победившую запись и применяет таблицу выше. Нельзя отвечать собственной маской до успешного сохранения. Для начального прототипа это проще распределённых блокировок, допускает только лишнее вычисление при гонке. [Redis SET](https://redis.io/docs/latest/commands/set/). Lua понадобится только если нужно атомарно связать несколько ключей/счётчиков; скрипт короткий, поскольку Redis выполняет его атомарно и блокирует другие операции на время исполнения. [Redis Lua](https://redis.io/docs/latest/develop/programmability/eval-intro/).

В случае потери Redis — `503`, без открытого текста и без перехода на несогласованное локальное состояние. При перегрузке — `429` с `Retry-After`; ошибку сохранения нельзя выдать как успешное маскирование. Простейшие обязательные конкурентные проверки: 20 одновременных одинаковых первых запросов, повтор каждого направления, два разных текста с одним ID, несколько workers, истечение TTL, перезапуск worker, недоступность Redis.

## Состояние, конфигурация и доступ

Память оценивать до большого прогона. 1000 HTTP-запросов/с за 300 с — 300 000 запросов; при одной паре из двух запросов ориентир 150 000 разных записей, но смесь/ретраи неизвестны. При 15-минутном TTL и непрерывных 500 новых пар/с может накопиться 450 000 записей. Умножать число записей на измеренный размер записи вместе с Redis overhead, шифрованием и токенами. Не хранить бессрочно и не предполагать, что короткие и 100 000-токенные записи равны по стоимости.

Выделить бюджет Redis после измерения RAM workers; оставить запас ОС и прокси. Для обязательного состояния использовать `noeviction`: произвольное вытеснение незавершённых пар ломает обратимость. Достигнутый лимит означает отказ принять новую пару с понятной ошибкой; уже принятые должны завершаться. Persistence отключить для временного демо-состояния, Redis не публиковать наружу. Это означает потерю соответствий после его перезапуска; явно описать. [Redis eviction](https://redis.io/docs/latest/develop/reference/eviction/).

Fernet из `cryptography` — практичный готовый вариант шифрования отдельных записей с проверкой целостности; ключ хранить в секрете окружения/файле вне Git и ZIP. Ключ един для всех workers. Fernet обрабатывает сообщение в памяти, поэтому размер и накладные расходы проверить на большом тексте. Само шифрование не заменяет изоляцию Redis, TTL и контроль доступа. [Fernet](https://cryptography.io/en/latest/fernet/).

Конфиг валидировать при запуске: системы и enabled; идентифицируемые типы; маскируемые типы; разрешение демаскирования; стратегия замены; правила сочетаний; TTL; размер тела; лимит состояния; версия политики. Расширение простых типов через валидируемый конфиг regex/словари, сложных — через небольшой интерфейс детектора. Произвольный Python из конфига не исполнять. Начальная безопасная поставка маскирует все поддерживаемые типы. Более слабая политика для демонстрации настроек не должна незаметно использоваться в защищённом LLM-маршруте. Сохранённая версия преобразования не замораживает авторизацию: доступ и право демаскирования проверяются по актуальной конфигурации при каждом обращении, включая старые пары.

Участник разрешил временно отключить доступ для публичного нагрузочного endpoint. Реализовать отдельный ограниченный по времени режим только `/process`, фиксированную тестовую систему и синтетические данные; это не переносится на административные endpoints, метрики, настройки и LLM-прокси. Показать нормальный режим с ключами и отдельными правами на обратную операцию. Отключение проверки доступа — известное исключение тестирования, а не доказательство защищённого демаскирования. TLS по IP с самоподписанным сертификатом совместим с описанным стендом; поддержку проверить ранним прогоном.

## Производительность: измерить, затем оптимизировать

CPU-детектор внутри `async`-обработчика не становится параллельным от ключевого слова. Выбрать простой путь выполнения с ограничением одновременно работающих тяжёлых задач; прогнать heartbeat/простые запросы одновременно с большим текстом. Не создавать неограниченный пул процессов на каждый worker. Разделять время детектирования, Redis, маскирования, детокенизации и внешней LLM.

Локальная таблица измерений до сдачи:

| Профиль | Что проверяем |
| --- | --- |
| Контракт, 1 worker, без LLM | Валидность пары, повторы и базовое время |
| Regex + контекст против того же набора с NER | Полнота/ложные срабатывания, CPU и память |
| 2/4/8 workers | Успешные RPS, p50/p95/p99, ошибки, RAM; выбрать лучший измеренный режим |
| Постепенная нагрузка 50/100/250/500/1000 RPS | Где начинается насыщение; ступени — план, не обещанные результаты |
| Повторяемые и уникальные тексты отдельно | Эффект кэша и скорость реального детектирования |
| До 100 000 токенов по явно указанному токенизатору | Нет усечения, падения или пропусков на стыках; точная обратимость |
| Реальный прокси LLM | Правильная граница данных и end-to-end latency отдельно от модуля |

В генераторе нагрузки новые ID между парами, второй запрос получает именно маску первого; контролировать проверку восстановленной строки, HTTP-коды и dropped iterations. Открытая модель нагрузки важна: фиксированная скорость поступления не должна падать из-за замедления сервиса и скрывать перегрузку. k6 описывает это различие; его скрипт должен быть создан разрешённой моделью, как и остальные файлы кода. [k6: open/closed load models](https://grafana.com/docs/k6/latest/using-k6/scenarios/concepts/open-vs-closed/).

Кэш детектирования возможен после измерения узкого места: ключ — HMAC текста плюс версия детекторов/политики, ограничение размера и TTL; значения — интервалы, без сырых ПД. Токены и соответствия генерировать отдельно для каждой пары. Кэш не должен менять результат и не должен подменять испытание уникальных текстов. Отдельно фиксировать hit rate.

Для 100 000 токенов NER сегментировать с перекрытием и исходными смещениями; regex для длинных контекстов также проверять на стыках. Не усекать вход ради latency. Лимит байт HTTP не доказывает лимит токенов; в отчёте указать tokenizer и одновременно символы/байты. 1000 RPS для короткого текста и поддержка одного большого текста — разные измерения; одновременность требований неизвестна.

## Метрики и демонстрация

Метрики: счётчик завершённых HTTP-запросов по маршруту/направлению/статусу; гистограммы времени модуля и этапов; число принятых/завершённых пар; отказы/ошибки; размер и количество state; detected/masked по типам. RPS считать как rate счётчика за явное окно; TPS — входные текстовые токены модуля в секунду по объявленному токенизатору. LLM prompt/completion tokens и скорость генерации — отдельные показатели, не смешивать с TPS детектора. Не использовать `payload_id`, текст, телефон, имя и свободные значения в labels.

Prometheus Python в multiprocess-режиме требует отдельной настройки и имеет ограничения; `/metrics` одного случайного worker не представляет весь сервис. Настроить multiprocess directory с очисткой до запуска процессов либо отдельно агрегировать метрики. Это проверить под 2 workers до нагрузочного отчёта. [Prometheus client multiprocess](https://prometheus.github.io/client_python/multiprocess/).

Логи каждого этапа: сгенерированный непрозрачный trace ID, система, типы/количества, этап, длительность, код результата. Не логировать тела, токены соответствий, ключи, исходные значения и полный `payload_id`. Проверить validation errors: стандартные ответы библиотек могут включать входные данные. На странице демо исходный текст допустим только как сознательно введённый синтетический пример; экран фактического outbound LLM payload показывает, что действительно ушло наружу. Не выдавать mock за реальный вызов; участник после исследования выбрал заглушку на текущий этап. Она проверяет путь данных и явно подписывается; реальная интеграция остаётся непроверенным ограничением, но не блокирует текущую реализацию. Доступ в расширении Kilo сам по себе не доказывает доступ из приложения.

## Дешёвые бонусы и порядок работ

Токенизация уже встроена в базовую обратимость и может дать один бонус. Второй кандидат — комбинационные правила PIN + карта в ограниченном контексте, настраиваемые по системе; не превращать их в default, который пропускает отдельно подписанный PIN. Третий — выбор вида маски по системе, только если второй режим корректно демаскируется и показан. Форматная маска без таблицы токенов плохо подходит изменённому ответу LLM; эту стоимость не скрывать. Поддержка ещё одного документа — альтернатива, если остаётся время на его варианты и отрицательные примеры. Не тратить резерв сдачи на попытку получить 2000 RPS без исходных замеров.

Порядок реализации: контракт и состояние → все 17 типов и обратимость → ранняя интеграция локального NER → политики/доступ/метрики → proxy с явно подписанной заглушкой → измерения/исправления → бонусы → README, схема, отчёт, презентация/скринкаст. Демо и нагрузку начать раньше полной полировки: риск недоступного endpoint дороже дополнительного детектора.

Перед развёртыванием сохранить список реально запущенных контейнеров, порты и команды восстановления. В разрешённое участником окно остановить их обратимо, запустить отдельный Compose-проект и выполнить smoke/нагрузочную проверку. Не использовать `down -v`, `prune`, удаление чужих контейнеров/volumes. Восстановить только исходно работавшие контейнеры после согласованного окна; не выключать оцениваемый сервис до завершения проверок. В этом документе приведён план; никакие контейнеры исследованием не остановлены.

Критерий готовности — воспроизводимая демонстрация защиты и обратимости на 17 категориях, работающая официальная пара, управляемые настройки, честные измерения и полный комплект сдачи. Числа качества/RPS записываются только после измерений; ни библиотека NER, ни выбранный стек сами по себе не доказывают 95% или 1000 RPS.
