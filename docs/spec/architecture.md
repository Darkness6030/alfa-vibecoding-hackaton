# Архитектура и границы решения 0.4.0

## Поток

`/process` → проверка системы и политики → поиск immutable-пары в Redis → при первом запросе детекция RU/EN → разрешение пересечений → маскирование → шифрование и атомарный SET NX EX → ответ. Повтор исходника возвращает ту же маску, собственная маска — оригинал после проверки актуального разрешения; другой текст для id даёт 409. При отсутствии обязательного хранилища успешного исходника вместо маски нет.

`/proxy` → защищённая полная token-политика → то же ядро → mock переставляет токены → повторная защита нового чувствительного содержимого → восстановление целых известных токенов. Неизвестные/утраченные токены дают предупреждение, не угадываются. В UI явно написано «заглушка»; реальный LLM не требуется по QA.

## Модули

| Область | Файлы |
|---|---|
| HTTP, ограничения, ошибки, auth и reload политик | `app/boundary.py`, `main.py`, `config.py`, `schemas.py`, `policy.py` |
| Интервалы, приоритеты, токены и восстановление | `app/core.py`, `engine.py` |
| Детекторы и общие лексические границы RU/EN | `app/detectors/` |
| Зашифрованные пары, изоляция, TTL и атомарность | `app/state.py` |
| Mock и безопасный демопрокси | `app/llm.py`, `proxy.py`, `static/demo.html` |
| Безопасные счётчики и этапные измерения | `app/metrics.py`, `tokenizer.py` |

Интервалы относятся к символам исходной Python-строки. Перевода и изменения регистра исходника нет. Приоритеты разрешают пересечения, но не заменяют правильные правила детекции. Новые токены содержат 128 случайных бит; таблица соответствий не кодируется в них. Redis хранит шифрованные оригинал/маску/типы; секрет и namespace одинаковы для workers. TTL 900 с абсолютный, повторы его не продлевают. Redis без persistence теряет пары после перезапуска — это явное ограничение демо.

## Что означает RU/EN

Распознаются те же 17 типов с русскими и английскими подписями/контекстами, а также смешанный текст. Добавлены английские месяцы, латинские имена с дефисом/апострофом и Unicode-буквами, подписи документов/ИНН, многословные адресные части и английские адреса вида `221B Baker Street, London`, международные телефоны с `+` и личной телефонной подписью. `Street`, как `ул.`, сохраняется в качестве служебного слова. Россия/другие гражданства распознаются в явно подписанном поле.

Полные российские серия+номер и отдельно подписанные части документов — разные правила. Четыре цифры около слова «паспорт» сами по себе не считаются серией. Даты выдачи не вытесняются совпадением года. Русское ФИО без подписи поддерживается эвристикой трёх слов с отчеством; произвольные двухсловные имена без контекста не гарантируются.

Это **не** универсальная поддержка паспортов/налоговых номеров всех стран. Английский INN означает тот же российский идентификатор с английской подписью; SSN/произвольные Tax ID не объявлены эквивалентными. Не гарантируются все географические формы, иностранные адреса, обфускации и намеренно повреждённые идентификаторы. Контекстные значения имеют ограниченное число слов; сложные длинные формулировки требуют дополнительных правил. Регистр не влияет на поиск, но типы и исходный текст сохраняются.

## Категории ТЗ

| Группа | Категории |
|---|---|
| Личные сведения | ФИО; дата рождения; место рождения; гражданство |
| Документы | Паспорт; кем выдан; код подразделения; дата выдачи; водительское удостоверение |
| Адрес и контакты | Адрес; электронная почта; телефон |
| Финансовые данные | ИНН; номер карты; CVV/CVC; PIN; имя держателя карты |

Всего 17 категорий; опциональная LOCATION от NER не считается дополнительной категорией ТЗ. Поддерживаемые формы проверяются `tests/test_categories.py`, `test_bilingual.py` и `test_scoring_matrix.py`.

## Политики и безопасность

JSON задаёт enabled, detect_types, mask_types, masking_enabled, demask_allowed, mask_mode и combinations. Новые простые типы добавляются через custom_patterns доверенным администратором. Это не sandbox произвольных regex. Безопасный proxy запрещает намеренно неполные/ослабленные политики. Открытый `/process` — исключение для синтетического стенда по QA, не production-профиль.

Служебные журналы содержат стадии, фиксированную категорию ошибки, типы и длительности; значения/ключи/mapping не записываются. HTTP и внутренние стадии измеряются отдельно; вложенные времена нельзя складывать как независимые. RPS/TPS вычисляются из счётчиков, TPS — технические пробельные токены. Для proxy журналируются типы и этапы mock/restore; для `/process` — detect/mask, state_read/state_write и общий transform. Redact не требует вызова token-mask, а повтор пары не вызывает повторную детекцию: отсутствие соответствующего этапа ожидаемо.

Открытый HTTP предназначен для синтетического стенда; HTTPS-демо может использовать self-signed сертификат. Защита токенизации относится к маскированному тексту без ключа/таблицы; одновременная компрометация всех компонентов и выводы по контексту не объявляются исключёнными. Банковская/юридическая сертификация не заявляется.

## Дополнение 0.3.1

Личные подписанные имена допускают инициалы до/после фамилии. Адресные правила включают корпус/строение, составной номер дома и явно подписанные UK/Canada/US ZIP+4 индексы. Это ограниченные форматы, а не универсальный парсер международных адресов.

## Производительность

Pure ASGI middleware ограничивает тело до запуска обработки, сохраняет 429/Retry-After и фиксированные категории ошибок. Готовые детекторы кэшируются по неизменяемому содержимому политики (LRU до 64 конфигураций); пользовательские тексты и результаты в этот кэш не попадают. Обратные запросы и повторы читают зашифрованную пару, не создают движок и не выполняют детекцию. Маскирование использует уже разрешённые интервалы без повторной сортировки. Включённые логи и шифрование остаются частью измеряемого пути.

Исходные токены индексируются во временное множество один раз на запрос, туда же добавляются сгенерированные значения. Проверка коллизий не сканирует весь исходник для каждой сущности. Тип Span ограничен грамматикой восстанавливаемого токена; границы и соответствие исходному тексту проверяются.

HTTP принимает до 8 МБ: непрозрачные токены могут быть длиннее исходных значений. Отдельная регрессия проверяет 100 000 email-токенов и обратный запрос с маской 4,3 МБ. Лимит записи Redis — 16 МБ; ограничения на байты остаются независимыми от числа технических токенов.

## Уточнения финального ревью 0.4.3

Имена и многословные значения поддерживают обычный, неразрывный U+00A0 и узкий неразрывный U+202F пробел без нормализации исходной строки. Отдельно подписанные поля имени и фамилии, номерные улицы, подписи «Имя держателя карты» и «Card holder name» имеют регрессионные проверки. Адрес офиса относится к отрицательному контексту; более близкая подпись домашнего адреса возвращает личный контекст. Это уточнение ограниченных правил, не обещание универсальной NER.

Для `/proxy` таблица соответствий живёт только в памяти одного вызова; Fernet/Redis обслуживает пары отдельных HTTP-запросов `/process`. Перед выдачей ответа proxy актуальные права проверяются повторно.

## HTTPS 0.4.4

Nginx 1.28 использует явный upstream keepalive (64 неактивных соединения), HTTP/1.1 и очищенный Connection header. Это позволяет повторно использовать соединения с API. Лимит worker_connections — 4096, worker_rlimit_nofile — 8192; у TLS-контейнера 128 MiB. До исправления нагрузочный HTTPS-прогон давал таймауты, тогда как прямой HTTP работал; повторный прогон проверил эффект настройки. Инструкция Nginx: [upstream keepalive](https://nginx.org/en/docs/http/ngx_http_upstream_module.html#keepalive). Конфиг и Compose overlay включены в минимальный ZIP.
